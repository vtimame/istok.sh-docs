Команда `istok` работает с тем же локальным состоянием, которое ваш агент использует через MCP. Она нужна, чтобы всё настроить, посмотреть, что записали агенты, синхронизировать устройства и писать скрипты; в повседневной работе агента она не нужна.

`istok COMMAND --help` — точный список флагов установленной у вас версии. На этой странице перечислены команды и важные флаги.

## Текущий проект

Большинство команд работают с проектом, в котором находится текущая директория. При вложенных проектах побеждает ближайший. Команды с флагом `--project` (или `-p`) принимают ID проекта, однозначный префикс ID или имя.

Почти все команды принимают `--database PATH` (или `ISTOK_DATABASE`) и `--json`.

## Команды

| Команда | Назначение |
| --- | --- |
| `istok init [PATH]` | Зарегистрировать текущую директорию или `PATH` как проект. `--name` задаёт имя. |
| `istok mcp` | Запустить MCP-сервер через stdin/stdout. См. [Инструменты MCP](/docs/ru/reference/mcp). |
| `istok project` | Показать проекты и управлять ими. |
| `istok task` | Создавать, просматривать и вести задачи. |
| `istok run` | Запуски, выполнения команд, проверки и артефакты. |
| `istok context` | Сохранённый контекст проекта: правила, решения, ограничения, заметки. |
| `istok knowledge` | Проверенные знания проекта. |
| `istok index`, `istok search`, `istok graph` | Локальный индекс кода, поиск по коду и граф кода. |
| `istok sync` | Синхронизация проектов между устройствами через хаб. |
| `istok hub` | Запуск хаба и управление его устройствами. |
| `istok export`, `istok import` | Перенос проектов через файл. |
| `istok hooks` | Установка хуков Istok в Claude Code или Codex. |
| `istok resume` | Показать прерванную работу текущего проекта. |
| `istok usage` | Отчёт о том, как агенты пользовались Istok через MCP на этом устройстве. |
| `istok update` | Проверить и установить новый релиз. |
| `istok completion [SHELL]` | Настроить автодополнение в shell. |
| `istok version` | Показать версию. |

## project

| Команда | Назначение |
| --- | --- |
| `project show [SELECTOR]` | Показать текущий проект или указанный. |
| `project list` | Список проектов; `--deleted` добавляет корзину. |
| `project rename NAME` | Переименовать текущий проект (или `--project`). |
| `project rebind SELECTOR [PATH]` | Привязать проект к новой папке, например после переноса репозитория. |
| `project delete` | Переместить текущий проект (или `--project`) в корзину. `--yes` пропускает подтверждение и обязателен с `--json`. |
| `project restore SELECTOR [PATH]` | Восстановить удалённый проект в прежней папке или в `PATH`. |

## task

Задачи указываются номером внутри проекта, например `12`.

| Команда | Назначение |
| --- | --- |
| `task create --title T` | Создать задачу; также `--description`, `--acceptance-criteria`, `--notes`. |
| `task list` | Список открытых задач; `--status open\|blocked\|done`, можно повторять. |
| `task ready` | Задачи, готовые к взятию. |
| `task show N` | Показать задачу с зависимостями, историей и привязанными коммитами. |
| `task comment N --body B` | Добавить комментарий. |
| `task progress N --body B` | Записать прогресс. |
| `task dependency add\|remove N --blocker M` | Сделать задачу `M` блокирующей для задачи `N` или убрать эту связь. |
| `task claim N` | Взять готовую задачу и начать запуск. Выводит ID запуска и его аренду. |
| `task done N --expected-revision R --note TEXT` | Завершить задачу с `--run-id` и `--validation-id` пройденной проверки или с `--override-reason`. |

`task claim` также принимает параметры контекста из `context preview` (ниже), `--base-branch` и `--base-commit`.

## run

Запуски указываются по UUID. Командам, которые меняют активный запуск, нужна его текущая аренда (`--lease`); при восстановлении аренда меняется.

| Команда | Назначение |
| --- | --- |
| `run list` | Список запусков; `--task N`, `--status`, `--limit`. |
| `run show ID` | Показать запуск со снимком контекста, выполнениями, проверками и артефактами. |
| `run exec ID --lease L -- CMD...` | Выполнить команду и сохранить её вывод как доказательство. |
| `run validate ID --lease L -- CMD...` | Выполнить проверку; код выхода решает, пройдена она или нет. `--summary` заменяет выведенное описание. |
| `run heartbeat ID --lease L` | Продлить аренду. |
| `run recover ID --reason TEXT` | Получить новую аренду своего запуска после истечения старой; `--force` меняет её досрочно. |
| `run abandon ID --expected-revision R --reason TEXT` | Прервать активный запуск; задача остаётся открытой. |
| `run finish ID --lease L --expected-revision R --status S --summary TEXT` | Завершить запуск со статусом `succeeded`, `failed`, `blocked` или `cancelled`. Для успеха нужна пройденная проверка или `--allow-unvalidated` с `--override-reason`. |
| `run artifact list RUN` | Список файлов, сохранённых запуском. |
| `run artifact verify ARTIFACT --run RUN` | Проверить размер и SHA-256 артефакта. |
| `run execution start\|finish` | Записать процесс, выполненный вне Istok. |
| `run validation record EXECUTION --run RUN ...` | Записать подтверждённую вручную проверку завершённого выполнения. |

`exec` и `validate` принимают `--cwd`, `--timeout` (30 минут для `exec`, 10 для `validate`), `--termination-grace`, `--output-limit` и `--allow-dangerous` с `--override-reason` для команд, которые Istok считает опасными.

Статусы запуска: `active`, `succeeded`, `failed`, `blocked`, `cancelled` (отменён) и `abandoned` (прерван).

## context

Записи контекста — короткие заметки, которые доставляются в запуски. Записи указываются по UUID; для изменений нужен `--expected-revision`.

| Команда | Назначение |
| --- | --- |
| `context add TITLE --body B` | Добавить запись. `--kind note\|decision\|instruction\|constraint`, `--delivery always\|ranked\|manual`, `--priority critical\|high\|normal\|low`, `--tag`, `--review-after`, `--expires-at`. |
| `context list`, `context search QUERY` | Список записей или поиск по ним; `--deleted`, `--include-disabled`, `--limit`. |
| `context show [ID]` | Показать одну запись или все в виде Markdown. |
| `context update ID` | Изменить любое поле. |
| `context enable\|disable ID` | Включить или выключить инструкцию. |
| `context delete ID` | Отправить запись в архив. |
| `context preview N` | Показать контекст, который получит взятие задачи `N`, не начиная запуск. |
| `context doctor` | Отчёт о размере контекста и записях, которые истекли, заменены или ждут пересмотра. |

`preview` и `claim` принимают `--context-limit` (1-64), `--context-id`, чтобы добавить записи по ID, и, с причиной для аудита, `--all-context` или `--without-retrieval`.

## knowledge

Знания — более длинные документы, которые проходят через черновик, ревью и продвижение. Элементы указываются по UUID; для изменений нужен `--expected-revision`.

| Команда | Назначение |
| --- | --- |
| `knowledge add TITLE --summary S` | Создать черновик; `--body` или `--body-file`, `--kind architecture\|domain\|decision\|runbook\|note`, `--tag`, `--source`. |
| `knowledge distill TITLE --summary S --source ...` | Создать черновик из явно указанных источников. |
| `knowledge list` (или `catalog`), `knowledge search QUERY` | Заголовки и краткие описания без текста; `--limit`, `--offset`, фильтры. |
| `knowledge show ID`, `knowledge read ID` | Один элемент целиком. |
| `knowledge update ID` | Изменить черновик. |
| `knowledge review ID --note TEXT` | Записать ревью черновика. |
| `knowledge promote ID` | Сделать проверенный черновик актуальным. |
| `knowledge supersede ID NEW_ID` | Заменить актуальное знание новым элементом. |
| `knowledge export ID --output FILE` | Записать элемент в файл; `--format markdown\|json`. Существующие файлы не перезаписываются. |

Источник записывается как `TYPE:ID[@REVISION][#DETAIL]`, где тип — `task`, `run`, `context`, `knowledge`, `repository` или `import`.

## index, search, graph

Индекс обновляется сам, когда он нужен поиску, чтению графа или взятию задачи.

| Команда | Назначение |
| --- | --- |
| `index status` | Состояние индекса текущего проекта. |
| `index rebuild` | Перестроить индекс с нуля, для починки. |
| `search QUERY` | Поиск по коду: текст, путь или символ; `--limit` (10). |
| `graph symbol NAME` | Найти символы по имени. |
| `graph neighbors NAME` | Связи символа; `--kind`, `--limit`. |
| `graph path FROM TO` | Пути между двумя символами; `--max-depth` (6), `--limit`. |

Граф поддерживает Go, TypeScript и JavaScript.

## sync

Синхронизация поддерживает проекты в одинаковом состоянии на нескольких устройствах через хаб, который вы запускаете сами. См. [Работа на другом устройстве](/docs/ru/guides/another-device).

| Команда | Назначение |
| --- | --- |
| `sync join CODE` | Подключиться к хабу по приглашению из `hub device add`. Первое устройство создаёт ключ синхронизации; остальные передают `--key` из `sync key`. |
| `sync key` | Показать ключ синхронизации, с которым подключаются другие устройства. |
| `sync enable` | Опубликовать текущий проект на хабе. В свежем клоне — получить в эту папку проект хаба из того же git-репозитория. |
| `sync enable --project ID` | Получить в текущую папку конкретный проект хаба. |
| `sync enable --new` | Опубликовать текущий проект, хотя на хабе уже есть другой проект того же репозитория. |
| `sync` (или `sync run`) | Получить изменения с хаба и отправить локальные; `--project` ограничивает одним проектом. |
| `sync projects` | Список проектов хаба с их репозиториями. |
| `sync status` | Хаб и проекты, которые синхронизирует это устройство. |
| `sync disable` | Перестать синхронизировать текущий проект на этом устройстве. Данные остаются здесь и на хабе. |

Все команды sync принимают `--sync-dir` (или `ISTOK_SYNC_DIR`) — директорию с ключом этого устройства и данными о подключении к хабу.

После подключения устройства синхронизация идёт сама: MCP-сервер получает изменения перед `task_start` и отправляет их через несколько секунд после каждой записи, а хуки синхронизируют проект при старте сессии и, с `--stop`, при её остановке. Пока проект синхронизируется, номера новых задач и взятие задач проходят через хаб, поэтому два устройства никогда не получат один номер и не будут работать над одной задачей. Без хаба и то и другое происходит локально и согласуется при следующей синхронизации.

## hub

| Команда | Назначение |
| --- | --- |
| `hub serve` | Запустить хаб. `--listen` (`:7443`), `--advertise HOST:PORT` для приглашений, `--data` — директория данных. |
| `hub device add NAME` | Вывести одноразовое приглашение; `--expires` (15 минут), `--address` заменяет объявленный адрес. |
| `hub device list` | Список устройств, включая отозванные. |
| `hub device revoke DEVICE` | Навсегда отключить устройство по имени или префиксу ID. |
| `hub backup FILE` | Записать согласованную копию базы хаба. |

Устройства и хаб закрепляют ключи друг друга через взаимный TLS, поэтому хабу не нужны домен, сертификат или прокси. Строки шифруются на устройстве; хаб не может их прочитать. Релизы публикуют образ `ghcr.io/vtimame/istok-hub`, который хранит данные в `/data`.

## export и import

| Команда | Назначение |
| --- | --- |
| `export` | Записать текущий проект в `istok-export-<time>.json`. `-p` (можно повторять) или `--all` выбирают проекты; `-o FILE` или `-o -` для stdout. |
| `import FILE` | Слить пакет с базой этого устройства; `-` читает stdin. `--dry-run` показывает, что изменится. |

Импорт сливает данные по тем же правилам, что и синхронизация. Пакеты из Istok 0.4.0 не импортируются в новые версии; обновите оба устройства.

## hooks, resume, usage

| Команда | Назначение |
| --- | --- |
| `hooks install claude\|codex` | Добавить хуки, которые показывают прерванную работу при старте сессии и синхронизируют проект. В Claude Code они также сохраняют состояние Istok в сводках при сжатии контекста и привязывают новые коммиты к задаче единственного активного запуска. |
| `hooks install ... --stop` | Также один раз попросить агента о передаче дел, когда он останавливается с устаревшей передачей. |
| `hooks install ... --scope project` | Установить только для текущего проекта; по умолчанию `user` охватывает все проекты. `--print` показывает настройки вместо записи. |
| `hooks status`, `hooks uninstall AGENT` | Показать или удалить хуки. Остальные настройки сохраняются, с резервной копией. |
| `resume` | Показать прерванную работу текущего проекта; `--actor` ограничивает одним агентом. |
| `usage` | Какие инструменты вызывают агенты, как часто они завершаются ошибкой и где агенты выпадают из порядка работы. `--since` (30 дней; журнал хранит 90), `--project`. |

## update, completion, version

| Команда | Назначение |
| --- | --- |
| `update` | Скачать, проверить и установить последний релиз. `--check` только проверяет; `--yes` пропускает подтверждение. Во время обновления делается резервная копия базы, и она восстанавливается, если миграция не удалась. |
| `completion [bash\|fish\|zsh]` | Вывести команду, которая включает автодополнение; `--code` выводит сам скрипт. |
| `version` | Показать версию. |

## Переменные окружения

Флаг важнее своей переменной.

| Переменная | Назначение |
| --- | --- |
| `ISTOK_DATABASE` | Путь к базе. |
| `ISTOK_INDEX_ROOT` | Корневая директория индексов кода. |
| `ISTOK_AGENT_ID`, `ISTOK_AGENT_NAME` | Идентичность агента в `istok mcp`; `ISTOK_AGENT_ID` также фильтрует `resume`. |
| `ISTOK_MCP_TOOLS` | Набор инструментов `istok mcp`: `core` или `full`. |
| `ISTOK_SYNC_DIR` | Ключ синхронизации этого устройства и данные о подключении к хабу. |
| `ISTOK_HUB_DATA` | Директория данных хаба. |
| `ISTOK_HUB_LISTEN` | Адрес, который слушает хаб. |
| `ISTOK_HUB_ADVERTISE` | `HOST:PORT`, по которому устройства обращаются к хабу. |

Команды, запущенные через `run exec`, `run validate` и соответствующие инструменты MCP, получают окружение по белому списку, а также `ISTOK_RUN_ID`, `ISTOK_EXECUTION_ID` и `ISTOK_PROJECT_ROOT`.

## Пути к данным

`<data-home>` — это `${XDG_DATA_HOME:-~/.local/share}` в Linux и `~/Library/Application Support` в macOS.

| Путь | Содержимое |
| --- | --- |
| `<data-home>/istok/istok.db` | Всё долговременное состояние (SQLite). Делайте резервные копии. |
| `<data-home>/istok/artifacts/` | Файлы, сохранённые запусками; рядом с файлом базы, если вы задали свою. |
| `<data-home>/istok/indexes/` | Индексы кода, перестраиваются по необходимости; резервная копия не нужна. |
| `<data-home>/istok/sync/` | Ключ устройства, данные о подключении к хабу и ключ синхронизации. |
| `<data-home>/istok-hub/` | Данные хаба, на машине, где он запущен. Копию делает `hub backup`. |

Istok ничего не пишет в ваши репозитории. В Linux и macOS база создаётся с правами `0600`, а директория данных по умолчанию — с `0700`; Istok отказывается работать с базой, которая является символической ссылкой или лежит в директории, доступной на запись другим пользователям. CLI, MCP-сервер и хуки должны использовать одну базу, чтобы видеть одно состояние.

## Вывод в JSON

`--json` выдаёт версионированный ответ для скриптов; вывод для людей может меняться.

```sh
istok task list --json
```

* У каждого ответа есть поле верхнего уровня `schema_version`: `"2"` для результатов запусков, `"1"` для остальных. Проверяйте его, прежде чем полагаться на структуру.
* Результаты поиска и графа несут собственный контракт (`istok.retrieval.v1`, `istok.graph.v1`); `knowledge export --format json` пишет `istok.knowledge-export.v1`.
* Результаты по задачам содержат и UUID задачи, и её номер в проекте.
* Результаты содержат ревизию, нужную для `--expected-revision`. Устаревшая ревизия приводит к ошибке, а не к перезаписи более нового состояния: прочитайте объект снова и повторите.
* Пустые коллекции — `[]`, никогда не `null`.
* Ошибки структурированы и имеют стабильные коды; ориентируйтесь на код, а не на текст сообщения.
* В режиме JSON подтверждение не запрашивается, поэтому разрушительным командам нужен `--yes`.
