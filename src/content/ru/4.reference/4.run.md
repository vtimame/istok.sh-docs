`istok run` работает с запусками — отдельными попытками выполнить задачу. Агенты делают всё это через MCP; CLI нужен, чтобы посмотреть состояние, разобраться с проблемой или управлять запуском напрямую. Понятия описаны в разделах [Задачи и запуски](/docs/ru/how-istok-works/tasks-and-runs) и [Проверки](/docs/ru/how-istok-works/validation).

## Команды

| Команда            | Назначение                                            |
| ------------------ | ----------------------------------------------------- |
| `list`             | Показать запуски.                                     |
| `show RUN_ID`      | Посмотреть запуск.                                    |
| `heartbeat RUN_ID` | Продлить активную аренду.                             |
| `exec RUN_ID`      | Выполнить управляемую команду внутри запуска.         |
| `validate RUN_ID`  | Выполнить проверочную команду и сохранить результат.  |
| `artifact list RUN_ID` | Показать артефакты, записанные для запуска.       |
| `artifact verify ARTIFACT_ID` | Проверить записанный артефакт.             |
| `finish RUN_ID`    | Завершить запуск.                                     |
| `recover RUN_ID`   | Восстановить запуск с новой арендой.                  |
| `abandon RUN_ID`   | Прервать попытку, оставив задачу открытой.            |
| `execution start RUN_ID` | Записать процесс, запущенный вне Istok.         |
| `execution finish EXECUTION_ID` | Записать результат такого процесса.      |
| `validation record EXECUTION_ID` | Записать заявленную (attested) проверку для завершённого выполнения. |

ID запусков — канонические значения UUIDv7.

## Список запусков

```sh
istok run list
istok run list --task 12
istok run list --status active --limit 20
```

Возможные статусы: `active`, `succeeded`, `failed`, `blocked`, `cancelled` и `abandoned`; `--status` можно повторять.

`run list` показывает только текущий проект. Запуски всех проектов, где идущие и зависшие запуски различаются, смотрите в ленте запусков [веб-интерфейса](/docs/ru/guides/web-ui).

## Посмотреть запуск

```sh
istok run show RUN_ID
```

Показывает состояние запуска, аренду, ревизию, снимок контекста, выполнения, проверки и артефакты. Здесь удобно взять текущую аренду или ревизию перед следующей операцией. [Веб-интерфейс](/docs/ru/guides/web-ui) показывает тот же запуск, а снимок контекста — в разделе **What the agent saw**.

## Аренда

Командам, которые выполняют или меняют работу внутри активного запуска, нужна его текущая аренда:

```sh
istok run heartbeat RUN_ID --lease LEASE
```

Аренду выдаёт взятие задачи или восстановление запуска. Если она сменилась, используйте новую.

## Сигнал активности

```sh
istok run heartbeat RUN_ID --lease LEASE
```

Сигнал активности (heartbeat) продлевает аренду, чтобы запуск не считался зависшим, пока идёт долгая работа.

## Выполнить команду

```sh
istok run exec RUN_ID --lease LEASE -- pnpm lint
istok run exec RUN_ID --lease LEASE -- \
  go test ./internal/orders -run TestGetOrder
```

Всё после `--` — это команда и её аргументы. Команда и её вывод сохраняются вместе с запуском.

## Проверить запуск

```sh
istok run validate RUN_ID --lease LEASE -- go test ./...
istok run validate RUN_ID --lease LEASE -- pnpm test
```

Результат становится доказательством проверки, на которое могут ссылаться `finish` и `istok task done`. `--summary` задаёт краткое описание проверки; без него описание строится из результата.

### Опции exec и validate

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--cwd` | `.` | Рабочая директория внутри текущего проекта. |
| `--timeout` | `30m` для `exec`, `10m` для `validate` | Максимальная длительность. |
| `--termination-grace` | `5s` | Пауза между TERM и KILL. |
| `--output-limit` | `1048576` (1 MiB) | Сколько байт максимум сохранять для каждого потока вывода. |
| `--allow-dangerous` | | Разрешить команду, классифицированную как опасная. Требует `--override-reason`. |

```sh
istok run exec RUN_ID \
  --lease LEASE \
  --cwd packages/api \
  -- pnpm test
```

Управляемые команды получают от родительского процесса не всё окружение, а только переменные из разрешённого списка, плюс `ISTOK_RUN_ID`, `ISTOK_EXECUTION_ID` и `ISTOK_PROJECT_ROOT`. См. [Настройка](/docs/ru/reference/configuration#переменные-для-управляемых-команд).

Используйте `--allow-dangerous`, только когда операции это действительно нужно; причина сохраняется:

```sh
istok run exec RUN_ID \
  --lease LEASE \
  --allow-dangerous \
  --override-reason "Required for the requested migration" \
  -- COMMAND
```

## Артефакты

```sh
istok run artifact list RUN_ID
istok run artifact verify ARTIFACT_ID --run RUN_ID
```

Артефакты связывают с запуском файлы, которые он создал. Их содержимое лежит в хранилище артефактов Istok, вне базы данных.

## Завершить запуск

```sh
istok run finish RUN_ID \
  --lease LEASE \
  --expected-revision REVISION \
  --status succeeded \
  --summary "Implemented and validated."
```

`finish` требует текущую аренду, ожидаемую ревизию, конечный статус (`succeeded`, `failed`, `blocked` или `cancelled`) и краткий итог. Чтобы завершить запуск как `succeeded`, нужна пройденная проверка и ни одного ещё работающего управляемого выполнения.

Если ни одна проверка не применима, завершите запуск без проверки явно:

```sh
istok run finish RUN_ID \
  --lease LEASE \
  --expected-revision REVISION \
  --status succeeded \
  --summary "Documentation-only change." \
  --allow-unvalidated \
  --override-reason "No automated checks apply to this change"
```

## Восстановить запуск

```sh
istok run recover RUN_ID --reason "Continuing interrupted work"
```

Восстановление выдаёт тому же запуску новую аренду. Оно работает только для исполнителя, которому принадлежит запуск; дальше используйте возвращённую аренду.

`--force` заменяет собственную аренду текущего исполнителя ещё до её истечения, например если токен потерян:

```sh
istok run recover RUN_ID \
  --force \
  --reason "Replacing stale local session"
```

## Прервать запуск

```sh
istok run abandon RUN_ID \
  --expected-revision REVISION \
  --reason "Implementation approach needs to be restarted"
```

Прерывание завершает попытку, оставляет её в истории со статусом `abandoned` и оставляет задачу открытой для нового взятия. Аренда не нужна, так что это работает и для запуска, чей агент уже пропал.

Команда CLI работает с любым активным запуском, поэтому сначала проверьте через `istok run show`, что над ним никто не работает. [Веб-интерфейс](/docs/ru/guides/web-ui) прерывает только зависшие запуски, а MCP-инструмент `run_abandon` доступен только в профилях supervisor и admin.

## Запись работы, сделанной вне Istok

`exec` и `validate` запускают команды сами. Если команда выполнялась в другом месте, запишите её:

```sh
istok run execution start RUN_ID --lease LEASE -- COMMAND
istok run execution finish EXECUTION_ID --run RUN_ID --expected-revision REVISION --status succeeded --exit-code 0
istok run validation record EXECUTION_ID --run RUN_ID --source attested --status passed --command "COMMAND" --summary "Checked manually"
```

Эти команды не запускают процесс. `execution finish` также принимает `--duration-ms`, `--signal` и `--timed-out`; `validation record` — `--exit-code` и `--duration-ms`. У проверки, записанной так, источник `attested`: её всегда можно отличить от проверок, которые Istok получил из команды, запущенной им самим.

## Ревизии

`finish`, `abandon` и `execution finish` принимают `--expected-revision`. Если запуск или выполнение изменились с момента чтения, команда завершается ошибкой, а не перезаписывает более новое состояние. Выполните `istok run show` и повторите с текущей ревизией.

## Вывод JSON

JSON-результаты запусков в CLI и MCP используют `"schema_version": "2"`. См. [Вывод JSON](/docs/ru/reference/json-output).

