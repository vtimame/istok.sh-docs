`istok mcp` запускает MCP-сервер, с которым ваш кодинг-агент общается через stdin и stdout. Чтобы подключить агента, пройдите [быстрый старт](/docs/ru/getting-started/quick-start).

```sh
istok mcp --actor-id claude --actor-name "Claude Code"
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--tools` | `core` | Какие инструменты показывать: `core` или `full`. Также `ISTOK_MCP_TOOLS`. |
| `--profile` | `worker` | Профиль инструментов: `worker`, `supervisor` или `admin`. |
| `--actor-id` | генерируется при старте | Постоянный ID агента. Также `ISTOK_AGENT_ID`. |
| `--actor-name` | `MCP Agent` | Отображаемое имя агента. Также `ISTOK_AGENT_NAME`. |
| `--database` | директория данных | Путь к базе. Также `ISTOK_DATABASE`. |

## Проект и агент

Каждый процесс сервера берёт проект директории, в которой его запустили (при вложенных проектах — ближайший), и одну идентичность агента, и сохраняет их до конца работы. Инструменты не могут указать на другой проект или подменить агента, поэтому одна глобальная настройка MCP подходит для всех репозиториев.

Дайте каждому агенту свой постоянный `--actor-id`, например `claude` или `codex`. Запуски, проверки и аренды принадлежат этому исполнителю: продолжить или восстановить запуск может только он сам. Без ID каждый процесс получает новый, и после перезапуска агент не сможет продолжить свой запуск.

Сервер также передаёт короткие инструкции с порядком работы; клиенты, которые поддерживают инструкции сервера, добавляют их в промпт агента.

## Основные инструменты

Набор `core` по умолчанию — это короткий порядок работы. Каждое определение инструмента занимает контекст агента, поэтому остальные доступны через `--tools full`.

| Инструмент | Назначение |
| --- | --- |
| `project_current` | Проект директории сервера. |
| `project_init` | Зарегистрировать директорию сервера как проект. |
| `task_ready`, `task_list`, `task_show` | Найти и прочитать задачи. |
| `task_start` | Создать задачу по `title`, взять её по `task_id` или продолжить свой запуск. Возвращает запуск, правила проекта, контекст задачи, найденный код и последнюю передачу дел. Можно вызывать повторно после перезапуска или сжатия контекста. |
| `task_progress` | Записать шаг. |
| `task_block` | Заблокировать задачу с указанием причины. |
| `task_handoff` | Записать, что сделано, где остановилась работа, принятые решения и следующий шаг. `task_start` возвращает эту запись. С `release: true` также завершает ваш запуск как отменённый и оставляет задачу открытой, чтобы другой агент мог сразу её начать; используйте, когда пользователь передаёт задачу другому агенту. Если у вас нет активного запуска задачи, записывается только передача дел. |
| `task_commit` | Привязать git-коммит (по умолчанию `HEAD`) к задаче; `repository` выбирает вложенный репозиторий. |
| `task_evidence` | Записать проверку, которую Istok не может выполнить сам, например прогон CI или ручной тест, `passed` или `failed`. Istok хранит её как слова агента. |
| `run_validate` | Выполнить проверку (тесты, сборку, линтер) через Istok: он сам запускает команду в проекте и сохраняет код возврата и вывод как доказательство. Принимает `task_id` взятой задачи или `run_id` с `lease_id`. Агентам предписано предпочитать его своей оболочке. |
| `task_done` | Завершить запуск и задачу одним вызовом. Использует последнюю пройденную проверку или закрывает задачу без проверки с `not_verified_reason`. |
| `run_recover` | Получить новую аренду своего запуска, если его нельзя продолжить. |
| `context_add`, `context_list`, `context_update` | Сохранить правило проекта, найти сохранённые правила, изменить правило. |
| `knowledge_search`, `knowledge_read` | Найти знания, затем прочитать один элемент. |
| `search` | Поиск по коду проекта. |

Ваши вызовы продлевают аренду запуска, а первый вызов после паузы возобновляет истёкшую аренду. `task_progress` и `task_block` принимают необязательный `expected_revision`; без него запись идёт в текущую ревизию.

Вызов инструмента не из показанного набора возвращает ошибку `tool_unavailable` с подсказкой запустить сервер с `--tools full`.

## Полный набор

`--tools full` добавляет все остальные инструменты профиля:

| Группа | Инструменты |
| --- | --- |
| Состояние | `health` |
| Задачи | `task_create`, `task_update`, `task_comment`, `task_unblock`, `task_dependency_add`, `task_dependency_remove`, `task_claim`, `task_complete` |
| Запуски | `run_list`, `run_show`, `run_exec`, `run_heartbeat`, `run_finish`, `run_artifact_list`, `run_artifact_verify`, `execution_start`, `execution_finish`, `validation_record` |
| Контекст | `context_enable`, `context_disable`, `context_show`, `context_search`, `context_package`, `context_preview`, `context_doctor` |
| Знания | `knowledge_catalog`, `knowledge_show`, `knowledge_create`, `knowledge_distill`, `knowledge_update`, `knowledge_review`, `knowledge_promote`, `knowledge_supersede` |
| Код | `index_status`, `index_rebuild`, `graph_symbol`, `graph_neighbors`, `graph_path` |

Они соответствуют одноимённым командам CLI; см. [Справочник CLI](/docs/ru/reference/cli). Экспорт знаний в файл доступен только в CLI.

## Профили

Профиль добавляет инструменты для работы с расширенными правами. Они показываются в обоих наборах, потому что профиль выбирают намеренно.

| Профиль | Добавляет |
| --- | --- |
| `worker` (по умолчанию) | Ничего: обычный порядок работы. |
| `supervisor` | `run_abandon`, чтобы прервать активный запуск, оставив задачу открытой. |
| `admin` | `run_abandon`, `project_list`, `project_rename`, `project_rebind`, `project_delete`, `project_restore`, `task_delete`, `task_restore`, `context_archive`. |

`project_rebind` и `project_restore` привязывают проект к директории сервера. Включайте расширенный профиль, только когда он действительно нужен агенту.

## Синхронизация

На устройстве, подключённом к хабу, сервер синхронизирует проект сам: получает изменения перед `task_start`, чтобы передача дел, записанная на другом устройстве, попала в результат, и отправляет их через несколько секунд после каждой записи и при выходе. Недоступный хаб задерживает `task_start` не больше чем на несколько секунд. Пока над задачей работает другое устройство, `task_start` отказывается её брать и называет это устройство. См. [Работа на другом устройстве](/docs/ru/guides/another-device).

## Результаты и статистика

Результаты — структурированные ответы с `schema_version` `"1"` или `"2"` для результатов запусков; пустые коллекции — `[]`. См. [Вывод в JSON](/docs/ru/reference/cli#вывод-в-json).

Сервер записывает вызовы инструментов на этом устройстве; `istok usage` строит по ним отчёт.
