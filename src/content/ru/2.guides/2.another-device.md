Istok хранит всё в локальной базе. Чтобы продолжить тот же проект на другом компьютере, поднимите **хаб** синхронизации на сервере, до которого дотягиваются ваши устройства, например на VPS или домашнем сервере. Дальше каждое устройство синхронизируется с хабом само. Здесь описано, как это настроить и чего ожидать.

На всех устройствах и на хабе должна быть одна и та же версия Istok. Сначала выполните `istok update` на каждом.

## Как это устроено

- Хаб хранит только строки, зашифрованные на ваших устройствах. Он держит задачи, запуски, контекст и знания, но прочитать их не может.
- У хаба и у каждого устройства свой ключ, и они проверяют отпечатки друг друга по взаимному TLS. Не нужны ни домен, ни удостоверяющий центр, ни обратный прокси — только `HOST:PORT`, до которого дотягиваются устройства.
- В репозиторий ничего не записывается.

## 1. Поднимите хаб

С Docker возьмите [`docker/hub/compose.yml`](https://github.com/vtimame/istok.sh/blob/main/docker/hub/compose.yml) из репозитория Istok и запустите его на сервере, указав адрес, по которому к нему будут обращаться устройства:

```sh
ISTOK_HUB_ADVERTISE=203.0.113.10:7443 docker compose up -d
```

Образ `ghcr.io/vtimame/istok-hub` публикуется с каждым релизом для x86-64 и ARM64. Он работает без привилегий и хранит данные в томе `hub-data`. `ISTOK_HUB_PORT` меняет опубликованный порт (по умолчанию 7443).

Без Docker запустите хаб бинарником `istok`:

```sh
istok hub serve --advertise 203.0.113.10:7443
```

Он слушает `:7443` (меняется через `--listen`) и хранит данные в `~/.local/share/istok-hub` (меняется через `--data`).

Если устройства попадают на хаб по-разному из разных сетей, перечислите все адреса через запятую, например адрес в домашней сети и адрес в Tailscale: `ISTOK_HUB_ADVERTISE=192.168.0.12:7443,100.126.4.13:7443`. Устройства пробуют их одновременно и используют первый, где отвечает именно ваш хаб.

## 2. Подключите первое устройство

На сервере хаба создайте приглашение для устройства:

```sh
docker compose exec hub istok hub device add laptop
# или без Docker:
istok hub device add laptop
```

Команда выводит одноразовый код, который действует 15 минут (меняется через `--expires`). На ноутбуке:

```sh
istok sync join CODE
```

Первое подключившееся устройство создаёт **ключ синхронизации** и выводит его. Этим ключом шифруются строки, и без него данные хаба прочитать нельзя. Храните его надёжно, как пароль. `istok sync key` выведет его снова.

Затем в папке проекта, который хотите синхронизировать:

```sh
istok sync enable
```

Команда публикует проект на хабе. Повторите её в папке каждого проекта, который нужно синхронизировать.

## 3. Добавьте другое устройство

Создайте на хабе новое приглашение (`istok hub device add desktop`). На новом устройстве подключитесь с ключом, который выводит `istok sync key` на первом:

```sh
istok sync join CODE --key istok-key-...
```

Затем склонируйте репозиторий и включите синхронизацию внутри клона:

```sh
git clone git@github.com:acme/acme-api.git
cd acme-api
istok sync enable
```

Istok находит проект этого репозитория на хабе по его git remote — как бы ни называлась папка и как бы ни был записан remote, через HTTPS или SSH, — загружает его и привязывает папку. Теперь задачи, история и правила есть и на этом устройстве.

- Чтобы загрузить проект с хаба в любую папку, передайте его ID: `istok sync enable --project ID`. `istok sync projects` показывает проекты хаба вместе с их remote.
- Если эта папка уже отдельный локальный проект, а на хабе есть другой проект того же репозитория, `istok sync enable` откажется публиковать дубликат и подскажет, что делать. `--new` всё равно опубликует его как отдельный проект.

## Что происходит само

Когда устройство подключено к хабу, запускать `istok sync` вручную почти не приходится:

- MCP-сервер загружает проект с хаба перед тем, как агент начнёт задачу, поэтому передача дел, записанная на другом устройстве, попадает в сводку. Изменения он отправляет через несколько секунд после каждой записи и при завершении.
- Хук `SessionStart`, а также хук `Stop`, если вы установили его с `--stop`, синхронизируют текущий проект.
- Чтение задач сначала синхронизирует проект: `istok task list`, `task show`, `task ready` и списки задач и запусков у агента, если проект не синхронизировался последние 30 секунд. Колонка WORKER в списке показывает, какой агент работает над задачей, на любом устройстве.
- `istok sync` вручную загружает и отправляет изменения всех синхронизируемых проектов; `--project` ограничивает его одним.

**Номера задач выдаёт хаб,** поэтому у задач, созданных на двух устройствах, номера не совпадают.

**Над задачей работает одно устройство.** Прежде чем начать задачу или продолжить на другом устройстве свой запуск, Istok спрашивает хаб. Пока над задачей работает другое устройство, старт отклоняется с именем этого устройства.

**Без связи работа продолжается локально.** Если хаб недоступен, каждый шаг ждёт его не больше пары секунд и продолжается без него. Задача, созданная без связи, получает локальный номер; если другое устройство тем временем заняло этот номер, при следующей синхронизации задача переходит на свободный, а в её историю добавляется заметка. Старт задачи без связи не сверяется с другими устройствами.

## Что синхронизируется, а что остаётся

Синхронизируются проекты, задачи с историей, запуски и их проверки, то, что видел каждый агент при взятии задачи, а также общий контекст и знания. Изменения сливаются по тем же правилам, что и в `istok import`: история дополняется, а если одну и ту же запись изменили на обеих сторонах, побеждает версия с большим числом изменений.

На каждом устройстве остаются: папки проектов, логи вывода команд, индекс кода и фрагменты кода, которые агенты из него получили, а также контекст и знания с пометкой `local_only`.

## Проверить и остановить

```sh
istok sync status     # хаб, это устройство и проекты, которые оно синхронизирует, со временем последней синхронизации
istok sync projects   # проекты хаба
istok sync disable    # перестать синхронизировать текущий проект на этом устройстве
```

На сервере хаба `istok hub device list` показывает устройства, `istok hub device revoke NAME` навсегда отключает одно из них, а `istok hub backup FILE` записывает согласованную копию базы хаба. Устройство, потерявшее базу, получает свои строки обратно с хаба.

## Без хаба: выгрузка и загрузка

Проекты по-прежнему можно переносить файлом, например на машину, которая не видит хаб:

```sh
istok export -o work.json            # текущий проект; --project NAME или --all для нескольких
istok import work.json --dry-run     # на другом устройстве: посмотреть, что изменится
istok import work.json
```

У загруженного проекта на новом устройстве ещё нет папки. Склонируйте репозиторий и привяжите его командой `istok project rebind acme-api ~/src/acme-api`. Повторная загрузка того же файла ничего не меняет. В файле ваша история задач и заметки по проекту; обращайтесь с ним как с личным документом.
