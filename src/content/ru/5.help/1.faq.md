Три команды отвечают на большинство вопросов:

```sh
istok version          # установлен ли Istok и какой версии
istok project show     # относится ли эта директория к проекту
istok COMMAND --help   # точные флаги вашей версии
```

## Вопросы

### Нужно ли мне самому создавать задачи?

Нет. Вы просто общаетесь с агентом; для существенной работы он находит подходящую задачу или создаёт новую. Вопросы, чтение кода и мелкие правки не отслеживаются. См. [Работа с агентом](/docs/ru/guides/working-with-agents).

### Можно ли настроить Istok один раз для всех репозиториев?

Да. Добавьте `istok mcp` в агента на уровне пользователя: каждый процесс сервера берёт проект директории, в которой его запустили. Каждый репозиторий всё равно нужно один раз зарегистрировать — попросив агента или командой `istok init`.

### Агент сам регистрирует репозитории?

Он вызывает `project_init` только по вашей просьбе. Инструкции сервера велят ему сообщить о незарегистрированной директории и продолжить без Istok.

### Могут ли несколько агентов работать с одним проектом?

Да. Codex может начать задачу, а Claude Code — продолжить. Дайте каждому агенту свой `--actor-id`, чтобы различать их запуски и чтобы каждый мог продолжить свою работу.

### Что будет, если сессия закончится посреди задачи?

Всё записанное сохраняется. Если агент записал передачу дел, следующий `task_start` вернёт её; с установленными хуками новая сессия начинается с прерванной работы. Её также показывает `istok resume`. См. [Как работает Istok](/docs/ru/how-istok-works/overview).

### Что будет, если проверка не прошла?

Неудача записывается в запуск, а задача остаётся открытой. Агент исправляет проблему и проверяет снова в том же запуске.

### Зачем и задачи, и запуски?

Задача — это то, что нужно сделать; запуск — одна попытка это сделать. Задача переживает прерванные и неудачные попытки, а каждый запуск хранит запись своей.

### Чем контекст отличается от знаний?

Записи контекста — короткие правила и заметки, которые доставляются в запуски автоматически. Знания — более длинные проверенные документы; агент ищет по ним и читает только нужное.

### Нужно ли обслуживать индекс кода?

Нет. Он обновляется сам, когда нужен поиску, чтению графа или взятию задачи. `istok index rebuild` нужен для починки.

### Есть ли графический интерфейс?

Нет. Используйте `istok task list`, `istok task show` и `istok run show` или спросите агента.

### Istok пишет файлы в мой репозиторий?

Нет. Всё состояние хранится в директории данных Istok. Знание становится файлом, только когда вы экспортируете его по выбранному вами пути. См. [Пути к данным](/docs/ru/reference/cli#пути-к-данным).

### Istok что-то куда-то отправляет?

Нет, если вы не настроили синхронизацию. Тогда данные уходят только на ваш собственный хаб, зашифрованными на устройстве; хаб не может их прочитать. Нет ни аккаунта, ни облачного сервиса.

## Агент и Istok

### Агент не видит инструменты Istok

Агент не может запустить `istok mcp`, чаще всего потому, что у редактора или десктопного приложения другой `PATH`, чем у терминала. Укажите в настройке MCP абсолютный путь к `istok`, перезапустите агента и проверьте статус MCP в нём. Настройка для каждого агента описана в [быстром старте](/docs/ru/getting-started/quick-start).

### Агент не пользуется Istok

Проверьте, что репозиторий зарегистрирован (`istok project show`) и что MCP-сервер агента запустился. Подсказки, как вернуть агента к Istok, есть в разделе [Работа с агентом](/docs/ru/guides/working-with-agents).

### Агенту нужен инструмент, которого нет в списке

Набор `core` по умолчанию содержит короткий порядок работы, а вызовы других инструментов возвращают `tool_unavailable`. Запустите сервер с `istok mcp --tools full` (или `ISTOK_MCP_TOOLS=full`), чтобы получить запись знаний, граф кода, зависимости и внутренние операции запусков. См. [Инструменты MCP](/docs/ru/reference/mcp).

### Istok не находит проект

Директория не входит в зарегистрированный проект. Проверьте `pwd` и `istok project list`, затем выполните `istok init` в репозитории или попросите агента зарегистрировать его.

### Я переместил или переименовал папку репозитория

Перепривяжите проект, а не регистрируйте новый, чтобы задачи остались при нём:

```sh
cd ~/projects/acme-api
istok project rebind acme-api
```

### CLI и агент показывают разные данные

Они используют разные базы. Каждый процесс читает `--database` или `ISTOK_DATABASE`, иначе путь по умолчанию. Передайте ту же базу в команду MCP агента.

## Задачи и запуски

### Задача застряла в работе

Её запуск остался без агента. Тот же агент продолжает его через `task_start` или восстанавливает через `run_recover`; после истечения аренды следующее взятие задачи закрывает старый запуск как `abandoned`. Если сессия агента ещё открыта, скажите ему остановиться и передать задачу: он завершит свой запуск вместе с передачей дел. Иначе, чтобы освободить задачу сразу, прервите запуск:

```sh
istok run list --task 12
istok run abandon RUN_ID --expected-revision REVISION --reason "Session ended"
```

Агенты могут прерывать запуски только с профилем `supervisor` или `admin`.

### Задачу нельзя взять

У неё есть активная блокирующая задача, её занимает другой запуск или она изменилась с тех пор, как вы её смотрели. Проверьте `istok task show 12`, `istok task ready` и `istok run list --task 12`.

### Взятие задачи не проходит из-за бюджета контекста

Записи, которые обязательно доставляются (записи `always` и записи, запрошенные по ID), не помещаются. Найдите их и сократите или переведите необязательные в `ranked`:

```sh
istok context doctor
istok context update RECORD_ID --expected-revision REVISION --delivery ranked
istok context preview 12
```

### Взятие задачи или поиск не проходит при подготовке индекса кода

Istok завершается ошибкой, а не работает с устаревшим кодом. Проверьте и почините:

```sh
istok index status
istok index rebuild
```

### Команда запуска отклоняет аренду

Аренда сменилась при восстановлении. Посмотрите текущую в `istok run show RUN_ID` или получите новую для своего запуска через `istok run recover RUN_ID --reason "Lost the lease"` (`--force`, если старая ещё действует).

### Операция не проходит из-за устаревшей ревизии

Объект изменился после того, как вы его прочитали. Прочитайте его снова и повторите с новой ревизией.

### Запуск нельзя завершить как succeeded

Для успеха нужны текущие аренда и ревизия, отсутствие незавершённых выполнений и пройденная проверка. Сначала запишите проверку или завершите запуск с `--allow-unvalidated` и `--override-reason`.

## Синхронизация и хаб

### Хаб недоступен

Команды sync завершаются ошибкой «cannot reach the hub». Проверьте, что `istok hub serve` работает, что адрес из `istok sync status` доступен с этого устройства и что порт открыт. Тем временем работа идёт локально: агенты и хуки ждут хаб не больше нескольких секунд, а следующая синхронизация отправит изменения.

### Устройство отозвано или его нужно подключить заново

Отозванное устройство отклоняется при подключении, и это тоже выглядит как «cannot reach the hub». Хаб навсегда отвергает его ключ, поэтому устройству нужен новый ключ: дайте ему новую директорию синхронизации (`--sync-dir` или `ISTOK_SYNC_DIR` либо переместите старую `<data-home>/istok/sync`), создайте новое приглашение командой `istok hub device add NAME` и подключитесь с ключом синхронизации с другого устройства:

```sh
istok sync join CODE --key KEY
```

### `sync enable` отказывается публиковать проект

На хабе уже есть проект того же git-репозитория, а эта папка принадлежит другому локальному проекту. Чтобы работать здесь с проектом хаба, удалите локальный и получите проект хаба:

```sh
istok project delete --project LOCAL_ID
istok sync enable
```

Чтобы опубликовать этот проект отдельно, выполните `istok sync enable --new`.

### У задачи сменился номер

Задача, созданная, пока хаб был недоступен, получает локальный номер. Если другое устройство за это время заняло этот номер, следующая синхронизация переносит задачу на свободный и отмечает это в её истории.

### Взятие задачи отклонено, потому что над ней работает другое устройство

Пока проект синхронизируется, над задачей одновременно работает только одно устройство. В ошибке указаны это устройство и время окончания его аренды. Выберите другую задачу, подождите или на том устройстве попросите агента передать задачу либо завершите или прервите запуск.

## Как сообщить о проблеме

Соберите `istok version`, `istok project show`, `istok index status`, а для нужной задачи — `istok task show N` и `istok run show RUN_ID`; для синхронизации — `istok sync status`. Для проблем с MCP приложите настройку MCP агента. Перед публикацией удалите секреты и закрытые данные.
