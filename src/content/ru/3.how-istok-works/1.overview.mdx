Здесь описаны несколько идей, на которых держится Istok: где он хранит данные, как отделяет работу от попыток, как записывает доказательства и что получает агент, когда начинает задачу.

## Проекты

Проект — это контейнер, в котором Istok хранит всё по одному репозиторию: задачи, запуски, проверки, сохранённый контекст, знания и индекс кода. Всё принадлежит проекту, а не разговору и не конкретному агенту, поэтому новая сессия или другой агент могут продолжить с того места, где остановился предыдущий.

Репозиторий регистрируют один раз, обычно попросив агента («Зарегистрируй этот проект в Istok») или командой `istok init`. Если директория уже зарегистрирована, возвращается существующий проект.

Istok определяет текущий проект по директории: MCP-сервер — по той, в которой запустили агента, команды CLI — по текущей. Поэтому одной записи `istok mcp` в пользовательской конфигурации хватает для всех репозиториев. Проекты могут быть вложенными, например приложение внутри монорепозитория; выигрывает ближайший.

Istok ничего не пишет в репозиторий. Всё состояние хранится локально:

```text
<data-home>/istok/
├── istok.db      проекты, задачи, запуски, контекст, знания (SQLite)
├── indexes/      индекс кода, по директории на проект
├── artifacts/    файлы, записанные запусками
└── sync/         членство этого устройства в хабе и ключ синхронизации, если вы синхронизируетесь
```

На Linux `<data-home>` — это `${XDG_DATA_HOME:-$HOME/.local/share}`, на macOS — `$HOME/Library/Application Support`. Перенесли репозиторий? `istok project rebind` укажет проекту новый путь, и история останется на месте.

## Задачи и запуски

Задача — это то, что нужно сделать. Запуск — одна попытка это сделать. Работа редко заканчивается за один раз: сессия обрывается, проверка не проходит или задачу берёт другой агент. Поэтому Istok хранит их отдельно:

```text
Task #12  "Return 404 for missing orders"
 ├── Run A   Claude Code   abandoned    (сессия закрыта)
 ├── Run B   Codex         failed       (тесты не прошли)
 └── Run C   Codex         succeeded    → задача выполнена
```

В задаче есть заголовок, описание, критерии приёмки, заметки, прогресс, блокеры, зависимости, привязанные коммиты и передачи дел. Она бывает **готова к работе**, **заблокирована** (ждёт другую задачу или помечена как заблокированная), **в работе** (у неё есть активный запуск) или **выполнена**.

Запуск начинается, когда агент начинает задачу. В нём записано, какой агент сделал попытку, с какой ветки и коммита Git он начал, какой контекст получил, какие команды выполнял и какие проверки прошёл. Запуск завершается как `succeeded`, `failed`, `blocked` или `cancelled` (отменён) либо как `abandoned`, если его бросили.

Пока запуск активен, он держит **аренду**, и каждый вызов Istok агентом её продлевает. Если агент замолкает, аренда истекает, и запуск становится **зависшим**. Тот же агент продолжает его следующим вызовом; другой агент, начиная задачу, закрывает его как `abandoned` и начинает новую попытку; `istok run abandon` сразу прерывает запуск. Прерванные запуски остаются в истории, а задача — открытой.

Перед тем как сессия закончится, агент записывает **передачу дел**: что сделано, где он остановился, какие решения принял и какой следующий шаг. Следующая сессия, которая начинает задачу, получает последнюю передачу дел вместе со свежими заметками и прошлыми запусками.

У задач и запусков есть номер ревизии, поэтому изменение, основанное на устаревшем состоянии, отклоняется, а не молча перезаписывает более новую работу.

## Проверки

Слова агента «готово, тесты проходят» — это просто заявление. Istok позволяет агенту приложить доказательство.

- **Проверка командой** — агент запускает через Istok команду, например `go test ./...`. Istok сохраняет команду, код завершения и вывод и по результату определяет, прошла проверка или нет.
- **Сообщённое доказательство** — проверка, сделанная в другом месте, например в CI или вручную, которую записал агент. Она помечается как засвидетельствованная (attested), чтобы её не спутали с командой, которую Istok выполнил сам.

Задача закрывается со ссылкой на прошедшую проверку своего запуска, так что за «готово» стоит доказательство. Если проверять нечего, например при правке только документации, агент должен сказать об этом и назвать причину, и причина сохраняется. Неудачная проверка ничего не стирает: агент исправляет проблему и проверяет снова, а неудача остаётся видна в истории.

Проверка привязана к коду, который она проверяла. Когда команда завершилась, Istok снимает отпечаток рабочего дерева проекта в Git: коммит и все изменения поверх него, включая неотслеживаемые файлы, которые не исключены `.gitignore`. При закрытии задачи Istok сравнивает дерево снова. Если код изменился после прошедшей проверки, закрыть задачу нельзя, пока агент не проверит заново, так что прошедшая проверка всегда описывает сданный код. Коммит проверенных изменений изменением не считается. В проекте без Git проверку не к чему привязать, и она помечается как не привязанная к коду.

Вывод команд ограничен (до 1 МиБ на поток), команды получают окружение по белому списку, а команды, которые Istok считает опасными, требуют явного разрешения с указанием причины.

## Контекст и знания

Istok запоминает о проекте два вида вещей, чтобы вам не повторять их в каждой сессии:

| | Записи контекста | Записи знаний |
| --- | --- | --- |
| Что это | Короткие правила, ограничения, решения, заметки | Длинные документы: архитектура, предметная область, runbook'и, выводы |
| Как попадают в запуск | Отобранные записи копируются целиком | Только заголовки и краткие описания; полный текст агент читает, когда нужно |
| Как меняются | Правятся на месте, с ревизиями | Черновик, ревью, утверждение, замена |

Когда агент начинает задачу, Istok собирает для запуска снимок контекста:

```text
записи always + записи, названные по ID + лучше всего подходящие записи ranked
        +
код из локального индекса, найденный для этой задачи
        +
сводка знаний: заголовки и краткие описания актуальных знаний
        ↓
снимок контекста  →  сохраняется вместе с запуском
```

Снимок фиксирован: если правило изменится посреди запуска, этот запуск сохранит то, с чем начинал. Кроме того, он ограничен по размеру, чтобы окно контекста агента не заполнялось посторонним: 16 КиБ и 12 записей сохранённого контекста, 32 КиБ кода и сводка не больше чем из 20 записей знаний. Записи `always` попадают первыми. Если обязательные записи не помещаются, старт задачи завершается ошибкой с их перечнем, а не отбрасывает ваши правила молча.

Агенты считают знания актуальной истиной, поэтому написание и принятие знаний — разные шаги:

```text
черновик  →  черновик после ревью  →  актуальное  →  заменённое
```

Править можно только черновики, и правка сбрасывает ревью. В сводки попадают только актуальные записи. У черновика может быть указан источник — задачи, запуски или файлы, из которых он получен, — чтобы проверяющий мог сверить его с ними.

Как сохранять правила и знания и как узнать, что увидел агент, — в разделе [Работа с агентом](/docs/ru/guides/working-with-agents). Как проекты переезжают между машинами — в разделе [Синхронизация между устройствами](/docs/ru/guides/another-device).
