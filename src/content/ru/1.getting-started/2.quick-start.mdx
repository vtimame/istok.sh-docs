Через пять минут ваш агент начнёт записывать работу в Istok: задачу, попытку её решить и проверки, которые подтверждают результат.

## 1. Установите Istok

```sh
curl -fsSL https://get.istok.sh | sh
istok version
```

Скрипт определяет систему, скачивает подходящий релиз, сверяет его с SHA-256-суммами релиза и кладёт `istok` в `~/.local/bin`. `sudo` не нужен. Если оболочка не находит `istok`, этой директории нет в `PATH`.

Релизы есть для Linux (x86-64, ARM64) и macOS (Intel, Apple Silicon). Windows пока не поддерживается.

Чтобы установить в другое место или конкретный релиз, передайте параметры после `sh -s --`:

```sh
curl -fsSL https://get.istok.sh | sh -s -- --install-dir "$HOME/bin"
curl -fsSL https://get.istok.sh | sh -s -- --version v0.4.0
```

Можно и скачать архив со страницы [GitHub Releases](https://github.com/vtimame/istok.sh/releases) и самостоятельно положить бинарник `istok` в `PATH`.

## 2. Подключите агента

Добавьте Istok как MCP-сервер один раз, на уровне пользователя. После этого подключение работает во всех проектах. По идентификатору исполнителя (actor ID) Istok понимает, какой агент сделал работу.

claude mcp add --transport stdio --scope user istok -- \

Сервер показывает основные инструменты рабочего процесса. Если нужны все инструменты, включая запись знаний и граф кода, добавьте `--tools full` к команде `istok mcp`.

## 3. Установите хуки

Для Claude Code и Codex хуки сохраняют работу между перезапусками и сжатиями контекста. Установите их один раз:

```sh
istok hooks install claude   # или: istok hooks install codex
```

Когда сессия начинается, хук выводит прерванную работу проекта, и агент видит её ещё до того, как вы что-то скажете. В Claude Code хуки также сохраняют состояние Istok в сводках при сжатии контекста и привязывают новые коммиты к задаче, над которой работает агент. С `--stop` агента один раз просят записать передачу дел, если он останавливается посреди задачи.

Вне проектов Istok хуки ничего не выводят. `istok hooks status` показывает, где они установлены; остальные настройки и хуки в конфигурации агента сохраняются.

## 4. Объясните агенту, когда им пользоваться

MCP делает инструменты доступными, а инструкции говорят агенту, когда их применять. Добавьте этот блок в глобальные инструкции: `~/.claude/CLAUDE.md` для Claude Code, `~/.codex/AGENTS.md` для Codex, User Rules в настройках Cursor.

```md
## Работа с Istok

Используй MCP-инструменты Istok для нетривиальной работы в репозиториях, зарегистрированных в Istok.

- Перед началом найди текущий проект в Istok. Если он не зарегистрирован, сообщи мне и не регистрируй его, пока я не попрошу.
- Используй подходящую существующую задачу, если она есть; иначе создай узкую задачу. Не создавай задачи для вопросов и мелких правок.
- Начни задачу до начала реализации и записывай заметный прогресс, решения и блокеры.
- Перед тем как остановиться, запиши передачу дел: что сделано, где остановился, следующий шаг.
- Проверяй результат через Istok и записывай подтверждения. Закрывай задачу только после успешной проверки.
- Не копируй состояние задач Istok в TODO-файлы и документы с планами.
```

MCP-сервер Istok и сам передаёт агенту короткую памятку по своим инструментам. Клиенты, которые поддерживают инструкции MCP-серверов, например Claude Code, показывают её агенту. Блок выше всё равно стоит добавить: он говорит, когда вы хотите, чтобы агент использовал Istok, и работает в любом клиенте. Подробная версия — в разделе [Работа с агентом](/docs/ru/guides/working-with-agents#если-агент-забывает-про-istok).

## 5. Зарегистрируйте проект

Запустите агента в своём репозитории и попросите:

<Prompt reply="Проект acme-api зарегистрирован в Istok.">Зарегистрируй этот проект в Istok.</Prompt>

Агент регистрирует директорию, в которой его запустили. Istok ничего не пишет в репозиторий. Из терминала то же самое делает `istok init`.

## 6. Дайте настоящую задачу

Попросите о том, о чём попросили бы в любом случае:

<Prompt>GET /orders/{"{id}"} отдаёт 500, если заказа нет. Пусть возвращает 404, а для остальных ошибок оставь 500.</Prompt>

Агент создаёт задачу, начинает её, пишет код, запускает тесты через Istok и закрывает задачу с этими подтверждениями. На простой вопрос он просто ответит.

## 7. Посмотрите, что произошло

```sh
istok task list
istok task show 1
```

`istok task list` показывает открытые задачи текущего проекта. `istok task show` выводит одну задачу с её историей, каждым запуском, проверками и привязанными коммитами.

## Обновление

```sh
istok update
```

Istok показывает текущую и новую версию с описанием изменений и спрашивает, прежде чем устанавливать. `--check` только проверяет наличие обновления; `--yes` устанавливает без вопроса. Перед заменой бинарника Istok проверяет подпись релиза, делает резервную копию базы и мигрирует её; если что-то пошло не так, возвращает старый бинарник и базу. Если вы используете свою базу, передайте её через `--database` или `ISTOK_DATABASE`, чтобы мигрировался нужный файл.

Уже открытая сессия агента продолжает работать со старым процессом `istok mcp`, поэтому после обновления начните новую сессию. Бинарник, собранный из исходников, обновить себя не может; `istok update` объяснит, как установить официальный релиз.

## Удаление

1. Удалите хуки: `istok hooks uninstall claude` (или `codex`).
2. Удалите MCP-сервер из настроек агента, например `claude mcp remove istok`.
3. Удалите бинарник: `rm ~/.local/bin/istok`.

Данные остаются на месте: `~/.local/share/istok` на Linux (или `$XDG_DATA_HOME/istok`), `~/Library/Application Support/istok` на macOS. Там лежат база, индексы кода, артефакты запусков и, если вы синхронизируетесь, ключ синхронизации этого устройства. Удаление этой директории стирает все проекты, задачи, запуски и знания на этой машине, и отменить это нельзя. Ваши репозитории это не затрагивает.
