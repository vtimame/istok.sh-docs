title: FAQ and troubleshooting
description: Short answers to common questions, and fixes for common problems.
---

Three commands answer most questions:

```sh
istok version          # is Istok installed, and which version
istok project show     # does this directory belong to a project
istok COMMAND --help   # the exact flags your version accepts
```

## Questions

### Do I need to create tasks myself?

No. You keep talking to your agent; for substantial work it finds an existing task or creates one. Questions, code reading and tiny edits are not tracked. See [Working with your agent](/docs/en/guides/working-with-agents).

### Can I set Istok up once for all repositories?

Yes. Add `istok mcp` to your agent at user scope: each server process takes the project of the directory it starts in. You still register each repository once, by asking the agent or with `istok init`.

### Will the agent register repositories on its own?

It calls `project_init` only when you ask. The server's instructions tell it to report an unregistered directory and continue without Istok.

### Can several agents work on one project?

Yes. Codex can start a task and Claude Code can continue it. Give each agent its own `--actor-id` so you can tell their runs apart and each can resume its own work.

### What happens when a session ends in the middle of a task?

Everything recorded stays. If the agent wrote a handoff, the next `task_start` returns it; with hooks installed, a new session starts with the interrupted work. `istok resume` prints it too. See [How Istok works](/docs/en/how-istok-works/overview).

### What happens if a check fails?

The failure is recorded in the run and the task stays open. The agent fixes the problem and checks again in the same run.

### Why both tasks and runs?

A task is what needs to be done; a run is one attempt at it. The task survives interrupted or failed attempts, and each run keeps the record of its own.

### How is context different from knowledge?

Context records are short rules and notes delivered to runs automatically. Knowledge items are longer, reviewed documents; the agent searches them and reads only what it needs.

### Do I need to maintain the code index?

No. It refreshes itself when search, graph reads or a claim need it. `istok index rebuild` is for repairs.

### Is there a graphical interface?

No. Use `istok task list`, `istok task show` and `istok run show`, or ask the agent.

### Does Istok write files into my repository?

No. All state lives in Istok's data directory. Knowledge becomes a file only when you export it to a path you choose. See [Data paths](/docs/en/reference/cli#data-paths).

### Is anything sent anywhere?

Not unless you set up sync. Then the data goes only to your own hub, encrypted on the device; the hub cannot read it. There is no account and no cloud service.

## The agent and Istok

### The agent does not see Istok tools

The agent cannot start `istok mcp`, most often because the editor or desktop app has a different `PATH` from your terminal. Use the absolute path of `istok` in the MCP configuration, restart the agent and check its MCP status view. Setup for each agent is in the [Quick start](/docs/en/getting-started/quick-start).

### The agent does not use Istok

Check that the repository is registered (`istok project show`) and that the agent's MCP server started. For prompts that steer an agent back, see [Working with your agent](/docs/en/guides/working-with-agents).

### The agent needs a tool that is not listed

The default `core` set lists the short workflow, and calls to other tools return `tool_unavailable`. Start the server with `istok mcp --tools full` (or `ISTOK_MCP_TOOLS=full`) for knowledge writing, the code graph, dependencies and run internals. See [MCP tools](/docs/en/reference/mcp).

### Istok cannot find the project

The directory is not inside a registered project. Check with `pwd` and `istok project list`, then run `istok init` in the repository or ask the agent to register it.

### I moved or renamed the repository folder

Rebind the project instead of registering a new one, so its tasks stay attached:

```sh
cd ~/projects/acme-api
istok project rebind acme-api
```

### The CLI and the agent show different data

They use different databases. Each process reads `--database` or `ISTOK_DATABASE`, or the default path. Pass the same database to the agent's MCP command.

## Tasks and runs

### A task is stuck in progress

Its run lost its agent. The same agent continues it with `task_start` or recovers it with `run_recover`; after the lease expires, the next claim closes the old run as `abandoned`. If the agent is still open, tell it to stop and hand the task over: it ends its run with the handoff. Otherwise, to release the task now, abandon the run:

```sh
istok run list --task 12
istok run abandon RUN_ID --expected-revision REVISION --reason "Session ended"
```

Agents can abandon runs only with the `supervisor` or `admin` profile.

### A task cannot be claimed

It has an active blocker, another run owns it, or it changed since you looked. Check `istok task show 12`, `istok task ready` and `istok run list --task 12`.

### A claim fails because of the context budget

The records that must be delivered (`always` records and records requested by ID) do not fit. Find them and shorten them, or move nonessential ones to `ranked`:

```sh
istok context doctor
istok context update RECORD_ID --expected-revision REVISION --delivery ranked
istok context preview 12
```

### A claim or search fails while preparing the code index

Istok fails instead of using stale code. Check and repair:

```sh
istok index status
istok index rebuild
```

### A run command rejects the lease

The lease changed on recovery. Read the current one with `istok run show RUN_ID`, or get a new one for your own run with `istok run recover RUN_ID --reason "Lost the lease"` (`--force` if the old one is still active).

### An operation fails with a stale revision

Something changed the object after you read it. Read it again and retry with the new revision.

### A run cannot be finished as succeeded

Success needs the current lease and revision, no running execution and a passed check. Record a check first, or finish with `--allow-unvalidated` and `--override-reason`.

## Sync and the hub

### The hub cannot be reached

Sync commands fail with "cannot reach the hub". Check that `istok hub serve` runs, that the address in `istok sync status` is reachable from this device, and that the port is open. Meanwhile work goes on locally: agents and hooks wait for the hub a few seconds at most, and the next sync sends the changes.

### A device was revoked, or needs to join again

A revoked device is rejected during the connection, which also shows as "cannot reach the hub". The hub refuses its key for good, so the device needs a new key: give it a fresh sync directory (`--sync-dir` or `ISTOK_SYNC_DIR`, or move the old `<data-home>/istok/sync` away), create a new invitation with `istok hub device add NAME` and join with the sync key from another device:

```sh
istok sync join CODE --key KEY
```

### `sync enable` refuses to publish a project

The hub already has a project of the same git repository, and this folder belongs to a different local project. To work on the hub project here, delete the local one and fetch the hub's:

```sh
istok project delete --project LOCAL_ID
istok sync enable
```

To publish this one as a separate project, run `istok sync enable --new`.

### A task changed its number

A task created while the hub was out of reach gets a local number. If another device took that number meanwhile, the next sync moves the task to a free one and notes it in the task's history.

### A claim is refused because another device works on the task

While a project syncs, one device works on a task at a time. The error names the device and when its lease ends. Pick another task, wait, or on that device tell the agent to hand the task over, or finish or abandon the run.

## Reporting a problem

Collect `istok version`, `istok project show`, `istok index status`, and for the task involved `istok task show N` and `istok run show RUN_ID`; for sync, `istok sync status`. For MCP problems, add the agent's MCP configuration. Remove secrets and private content before sharing.
