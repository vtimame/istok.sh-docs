---
title: istok ui
description: Serve the local web UI and manage it as a systemd user service.
---

`istok ui` serves the web UI built into the Istok binary and, on Linux, manages it as a background service. For what the UI shows, see the [Web UI guide](/docs/en/guides/web-ui); for setting up the service step by step, see [Updates and running the UI as a service](/docs/en/guides/updates-and-service).

## Commands

| Command                    | Purpose                                                        |
| -------------------------- | -------------------------------------------------------------- |
| `serve`                    | Serve the web UI in the foreground. This is the default.       |
| `service install`          | Create or update the user unit, enable it, and (re)start it.   |
| `service uninstall`        | Stop and disable the service and remove its unit.              |
| `service start`            | Start the service.                                             |
| `service stop`             | Stop the service.                                              |
| `service restart`          | Restart the service.                                           |
| `service status`           | Show the service status.                                       |

## Serve the UI

```sh
istok ui
```

is the same as:

```sh
istok ui serve
```

Istok listens on `127.0.0.1`, prints the address, and opens it in your default browser:

```text
Istok UI: http://127.0.0.1:7700/
Press Ctrl+C to stop.
```

If no browser can be opened, Istok prints a note and keeps serving; open the address manually.

Flags:

| Flag              | Default | Purpose                                                          |
| ----------------- | ------- | ---------------------------------------------------------------- |
| `--port`          | `7700`  | Loopback port. `0` picks a free port. Also `ISTOK_UI_PORT`.       |
| `--no-open`       |         | Print the address without opening a browser.                     |
| `--database PATH` |         | Path to the SQLite database. Also `ISTOK_DATABASE`.               |

For example:

```sh
istok ui --port 7800 --no-open
```

If the port is already in use, the command fails and suggests choosing another one with `--port`.

The UI is reachable only from the local machine. It has no login or token; see the [Web UI guide](/docs/en/guides/web-ui) for what this protects against and what it does not.

## Run as a service

`istok ui service` manages a systemd **user** unit named `istok-ui.service`. It requires Linux with systemd. On other systems the command reports that it is not supported; run `istok ui` directly instead.

No root access is needed. The unit file lives in:

```text
${XDG_CONFIG_HOME:-$HOME/.config}/systemd/user/istok-ui.service
```

The unit is regenerated on every `install`, so do not edit it by hand.

### Install

```sh
istok ui service install
```

`install` writes the unit, reloads systemd if the unit changed, enables the service, and restarts it. It prints the unit path, the binary the service runs, and the address:

```text
Istok UI: http://127.0.0.1:7700/
```

The service runs the absolute path of the `istok` binary you used for `install`, with `ui --no-open` and the chosen port.

Flags:

| Flag              | Default | Purpose                                                                    |
| ----------------- | ------- | -------------------------------------------------------------------------- |
| `--port`          | `7700`  | Loopback port the service listens on. Also `ISTOK_UI_PORT`.                |
| `--database PATH` |         | Path to the SQLite database, recorded in the unit. Also `ISTOK_DATABASE`.  |

The service does not inherit your shell environment. If you use a custom database, pass it to `install` (or have `ISTOK_DATABASE` set when you run it) so the absolute path is written into the unit.

Run `install` again to change the port or database, or to move the service to a different `istok` binary.

### Keep it running after logout

systemd stops user services when your last session ends unless lingering is enabled for your user:

```sh
loginctl enable-linger
```

### Control the service

```sh
istok ui service status
istok ui service stop
istok ui service start
istok ui service restart
```

These commands call `systemctl --user` for `istok-ui.service`. An inactive service is reported by `status` without being treated as an error.

### Uninstall

```sh
istok ui service uninstall
```

This disables and stops the service, removes the unit file, and reloads systemd.

## Updates

After a successful `istok update`, Istok restarts the service if all of these are true:

* the unit is installed;
* the service is active;
* the unit runs the binary that was just updated.

When the restart happens, `istok update` prints:

```text
Restarted the web UI service on the new binary.
```

If the restart fails, the update still counts as successful and Istok prints a warning. Restart it yourself with `istok ui service restart`.
