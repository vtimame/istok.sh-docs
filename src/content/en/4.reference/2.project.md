---
title: istok project
description: Show, list, rename, rebind, delete, and restore Istok projects. Also covers istok init.
---

`istok project` shows and manages registered projects. For what a project is and where its data lives, see [Projects](/docs/en/how-istok-works/projects).

## Commands

| Command                   | Purpose                                               |
| ------------------------- | ----------------------------------------------------- |
| `show [SELECTOR]`         | Show a project.                                       |
| `list`                    | List registered projects.                             |
| `rename NAME`             | Rename a project.                                     |
| `rebind SELECTOR [PATH]`  | Bind a project to a different repository path.       |
| `delete`                  | Move a project to the recoverable trash.              |
| `restore SELECTOR [PATH]` | Restore a deleted project.                            |

Without a selector, commands use the project that contains the current directory; with nested projects, the closest root wins.

## Selectors

`SELECTOR` can be:

* the project ID;
* an unambiguous ID prefix;
* the project name.

```sh
istok project show acme-api
istok project show 01a00b35
```

Names do not have to be unique. If a selector matches more than one project, Istok reports it as ambiguous; use the ID or a longer prefix.

## Register a project: `istok init`

```sh
cd ~/work/acme-api
istok init
```

This registers the directory and builds the first code index. Running it again in a directory that is already a project root returns the existing project. Agents do the same with the MCP tool `project_init`.

A project can be registered inside another project's directory, for example an app inside a monorepo:

```sh
cd ~/work/platform
istok init

cd ~/work/platform/apps/web
istok init
```

Both projects stay independent. Commands and MCP servers started inside `apps/web` use `web`; everywhere else in `~/work/platform` they use `platform`. Two active projects cannot have exactly the same root.

## Show a project

```sh
istok project show
istok project show acme-api
```

Shows the project's identity, state, and repository binding.

## List projects

```sh
istok project list
```

The output shows each project's name, state, and full repository root path. Deleted projects are hidden; include them to find one to restore:

```sh
istok project list --deleted
```

## Rename a project

```sh
istok project rename new-name
istok project rename new-name --project acme-api
```

Changes only the Istok name, not the directory or any state.

## Rebind a project

If a repository moves, rebind the existing project instead of registering a new one:

```sh
mv ~/work/acme-api ~/projects/acme-api
cd ~/projects/acme-api
istok project rebind acme-api
```

Without `PATH`, the current directory is used. You can also pass it explicitly:

```sh
istok project rebind acme-api /path/to/repository
```

Tasks, context, runs, and all other state stay with the project.

## Delete a project

```sh
istok project delete
istok project delete --project acme-api
```

Istok asks for confirmation; `--yes` skips it, and is required with `--json` so the command does not wait for input.

Deleting does **not** touch the repository or its files. The project is kept in a recoverable state with its tasks, runs, and history, and its directory is released so another project can use it. You can also delete a project from the [web UI](/docs/en/guides/web-ui); the result is the same.

## Restore a project

```sh
istok project restore acme-api
istok project restore acme-api /path/to/repository
```

Without a path, Istok reuses the project's previous root. If that directory no longer exists, the command fails and asks for a path. Restoring fails if another active project already uses the directory.

## Help

```sh
istok project show --help
istok project rebind --help
istok project restore --help
```
