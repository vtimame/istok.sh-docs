Knowledge is durable project documentation that Istok manages for you: architecture overviews, domain explanations, decisions, runbooks, and distilled investigation results.

It complements [project context](/docs/en/how-istok-works/context). Context records are short and can be delivered to agents automatically when they claim a task. Knowledge items can be long, so Istok does not push them into every run. Agents pull them when the work needs them.

## Why knowledge is pull-first

A coding agent works within a limited context window. If every run received every document the project has ever accumulated, most of that space would be spent on material that has nothing to do with the task.

Istok therefore gives a run only a short **briefing**: the titles and summaries of the project's current knowledge. The briefing is limited to 20 items and 4 KiB, separate from the [context budget](/docs/en/how-istok-works/context#bounded-context). It never contains full bodies or provenance.

When the briefing suggests that a document is relevant, the agent searches the catalog and reads only that item:

```text
Run starts
   ↓
Briefing: titles and summaries
   ↓
Agent searches the catalog when needed
   ↓
Agent reads one complete item
```

Catalog and search results contain metadata and short snippets, not full bodies. A complete body is returned only when an item is explicitly read.

## Draft, review, promote

Knowledge that agents rely on should be checked by someone. Istok separates writing knowledge from accepting it.

Every new item starts as a **draft**. An item can then move through these states:

```text
draft
  ↓  review (with a note)
reviewed draft
  ↓  promote
current
  ↓  supersede with a reviewed replacement
superseded
```

* **Draft** — a proposed item. Only drafts can be edited. Editing a draft clears any earlier review, so the changed text must be reviewed again.
* **Review** — an explicit record that someone checked the draft, together with a note describing the check, for example "Verified against the current code".
* **Current** — a promoted item. Only reviewed drafts can be promoted. Current items are the ones that appear in run briefings.
* **Superseded** — a current item that was replaced. It stays readable for history but no longer appears as current truth.

Current and superseded items cannot be edited. To change current knowledge, create a new draft, review it, and supersede the old item with it. This way an agent never reads an unreviewed edit as current truth.

## Distilling knowledge with provenance

Useful knowledge often comes out of work that has already happened: a long investigation, a run that uncovered how a subsystem really behaves, or a decision recorded in task history.

**Distilling** creates a draft from that work and records where it came from. Each source is a reference such as a task, a run, a context record, another knowledge item, a repository file, or an import. A distilled draft must have at least one source.

Provenance lets a reviewer check the draft against its origins before promoting it, and lets a later reader see why the item says what it says.

A typical agent-driven flow looks like this:

1. An agent finishes an investigation and distills the result into a draft that references the task and run.
2. You, or an agent you trust with the review, verify the draft against the current code and record a review note.
3. The reviewed draft is promoted to current.
4. When the facts change, a replacement draft goes through the same review and supersedes the old item.

## Where knowledge lives

Knowledge is stored in the Istok database, outside your repository. Istok never writes knowledge files into the project directory, and repository documentation stays yours to manage.

Repository files can still be referenced as provenance without being modified.

When you want a knowledge item as a file, export it explicitly to a path you choose:

```sh
istok knowledge export KNOWLEDGE_ID --output ~/notes/authentication.md
```

Export writes Markdown by default (JSON is also available) and refuses to overwrite an existing file.

## Knowledge and context

The two are easy to confuse, so here is the short version:

| | Context | Knowledge |
| --- | --- | --- |
| Typical content | Short instructions, constraints, decisions, notes | Longer documentation and distilled results |
| Delivery to a run | Selected records are copied into the snapshot | Only a briefing of titles and summaries |
| Changes | Edited in place with revisions | Draft, review, promote, supersede |

Use context for things an agent should know at the start of a task. Use knowledge for reference material an agent should be able to find and read when it becomes relevant.

## Inspecting knowledge

Agents normally manage knowledge through MCP. You can browse it in the [web UI](/docs/en/guides/web-ui) from a project's **Knowledge** page, or from the CLI:

```sh
istok knowledge list --status current
istok knowledge search "token refresh"
istok knowledge read KNOWLEDGE_ID
```

The full command surface is documented in the [knowledge reference](/docs/en/reference/knowledge).
