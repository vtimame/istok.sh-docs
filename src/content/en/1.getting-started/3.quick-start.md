This guide takes you from an existing repository to a coding agent that can use Istok as part of its normal workflow.

## Initialize your project

Open the repository you want to use with Istok:

```sh
cd my-project
```

Initialize it:

```sh
istok init
```

Istok registers the repository as a local project and prepares the project state used by coding agents.

You only need to initialize a repository once.

## Connect your coding agent

Istok exposes its tools to coding agents through MCP.

The server command is:

```sh
istok mcp
```

When configuring an agent, give it a stable actor ID. Istok uses this identity to associate runs, validation, and other recorded work with the agent that performed it.

For example:

```sh
istok mcp --actor-id codex --actor-name "Codex"
```

`--actor-id` is the stable identity stored with agent activity. `--actor-name` provides a human-readable name for that identity.

For personal use, simple IDs such as `codex`, `claude`, `antigravity`, and `cursor` work well.

If `--actor-id` is omitted, Istok creates a unique actor identity for that MCP process instead.

### Codex

Add Istok as an MCP server:

```sh
codex mcp add istok -- \
  istok mcp \
  --actor-id codex \
  --actor-name "Codex"
```

The global configuration can be used from any repository that you have initialized with Istok.

### Claude Code

Add Istok at user scope:

```sh
claude mcp add \
  --transport stdio \
  --scope user \
  istok -- \
  istok mcp \
  --actor-id claude \
  --actor-name "Claude Code"
```

You can inspect configured MCP servers from Claude Code with:

```text
/mcp
```

### Antigravity CLI

Antigravity CLI uses `mcp_config.json` for MCP servers.

Create or update:

```text
~/.gemini/config/mcp_config.json
```

Add Istok:

```json
{
  "mcpServers": {
    "istok": {
      "command": "istok",
      "args": [
        "mcp",
        "--actor-id",
        "antigravity",
        "--actor-name",
        "Antigravity CLI"
      ]
    }
  }
}
```

Start Antigravity CLI as usual:

```sh
agy
```

You can inspect configured MCP servers with:

```text
/mcp
```

### Cursor

Create or update the global MCP configuration:

```text
~/.cursor/mcp.json
```

Add Istok:

```json
{
  "mcpServers": {
    "istok": {
      "command": "istok",
      "args": [
        "mcp",
        "--actor-id",
        "cursor",
        "--actor-name",
        "Cursor"
      ]
    }
  }
}
```

With stable actor IDs, work performed through different agents remains attributable in Istok project state.

For example:

```text
Task
 ├── Run by codex
 │    └── validation
 │
 └── Run by claude
      └── validation
```

## Add recommended instructions

Connecting MCP makes Istok available to the agent. Instructions tell the agent when and how to use it.

For a personal default, add the Istok workflow to your agent's global instructions:

* **Codex:** `~/.codex/AGENTS.md`
* **Claude Code:** `~/.claude/CLAUDE.md`
* **Antigravity CLI:** `~/.gemini/GEMINI.md`
* **Cursor:** User Rules in Cursor settings

Add:

```md
## Working with Istok

Use Istok as the preferred source of durable project state for non-trivial work
when the current repository is registered with Istok.

Before starting non-trivial work:

1. Identify the current repository and check it through Istok MCP.
2. If the project is registered, use Istok to manage the work.
3. If the project is not registered, do not initialize it automatically.
   Tell the user and continue without Istok unless they ask to initialize it.

When working through Istok:

- Look for an existing relevant task before creating a new one.
- Do not create duplicate tasks.
- Create a task for new non-trivial work when no suitable task exists.
- Claim the task before making implementation changes.
- Use the context provided by Istok as the starting context for the work.
- Record meaningful progress, decisions, dependencies, and blockers in Istok.
- Preserve final validation results in Istok.
- Complete the work only after implementation and validation succeed.

Simple questions, code reading, and small consultations do not require a task.

Do not duplicate active Istok task state in temporary TODO files, plans, or
status documents.

If Istok MCP is unavailable, tell the user instead of guessing or inventing
project state.
```

With these instructions, the agent uses Istok automatically for initialized repositories while leaving other repositories unchanged.

## Start working

Setup is complete.

Continue talking to your coding agent normally. You do not need to manually create tasks, claim runs, prepare context, or manage validation.

For example:

> Investigate why authentication requests sometimes time out and fix the problem.

For non-trivial work, the agent can use Istok to:

1. find an existing relevant task or create one;
2. claim the task and begin a run under its actor identity;
3. retrieve the context needed for the work;
4. record meaningful progress, decisions, dependencies, and blockers;
5. preserve validation results;
6. leave durable project state that another session or agent can inspect later.

For simple questions, code reading, and small consultations, the agent can respond directly without creating unnecessary project state.

Istok runs underneath the workflow rather than replacing your normal interaction with the coding agent.

## Use project instructions for stricter workflows

Global instructions are a good personal default.

For a repository where Istok should be an explicit part of the development workflow, you can also keep stricter instructions in the repository itself.

Use:

* **Codex:** `AGENTS.md`
* **Claude Code:** `CLAUDE.md`
* **Antigravity CLI:** `AGENTS.md`
* **Cursor:** `AGENTS.md`

`AGENTS.md` can therefore be shared by Codex, Antigravity CLI, and Cursor. If the repository also uses Claude Code, add the corresponding Istok instructions to `CLAUDE.md`.

Project instructions can be committed with the repository so developers and coding agents use the same workflow.

Add:

```md
## Working with Istok

This project uses Istok as the source of truth for durable tasks, project
context, progress, runs, and validation results.

For any non-trivial work:

1. Check the current project through Istok MCP.
2. Find and load an existing relevant task and its context.
3. If no suitable task exists, create one before implementation.
4. Claim the task before modifying project files.
5. Record meaningful progress, decisions, dependencies, and blockers in Istok.
6. Preserve final validation results in Istok.
7. Finish the work only after implementation and validation succeed.

If the current repository is not registered with Istok, stop and tell the user.
Do not initialize a project without explicit permission and do not use another
Istok project instead.

Do not replace Istok task state with local TODO files, plans, or status reports.
```

You can keep the general Istok workflow in global instructions and use the project file for stricter or repository-specific guidance.

## Continue in another session

Istok state belongs to the project rather than to a particular conversation.

When you start a new session, the agent can inspect existing tasks, context, runs, and validation state instead of relying only on previous chat history.

Because each configured agent has a stable actor identity, the project history can also preserve which agent performed each attempt.

Work can therefore move between sessions or agents without requiring them to share conversation history.

You continue working with the agent as usual; Istok provides the durable state underneath that workflow.
