In about five minutes your agent will record its work in Istok: a task, the attempt, and the checks that prove the result.

## Claude Code: the plugin

With Claude Code, the shortest way is the plugin. Run this inside Claude Code:

```text
/plugin install istok --marketplace vtimame/istok.sh
```

The plugin connects the MCP server and adds the hooks, so you can skip steps 1–3 and continue from [step 4](#4-tell-the-agent-when-to-use-it). It runs the `istok` on your `PATH` when that one is recent enough. Otherwise, on first use it downloads the latest release into the plugin's data directory and checks its SHA-256 checksum and release signature before running it. That copy is available to the agent but not in your own terminal; to run `istok task list` yourself, install Istok as in step 1 too.

If you already connected Istok with `claude mcp add`, remove that server with `claude mcp remove istok`: otherwise the agent gets every tool twice. Hooks from `istok hooks install` can stay; the plugin's hooks then step aside.

## 1. Install

```sh
curl -fsSL https://get.istok.sh | sh
istok version
```

The script detects your system, downloads the matching release, checks it against the release's SHA-256 checksums and puts `istok` in `~/.local/bin`. It does not need `sudo`. If your shell cannot find `istok`, that directory is not on your `PATH`.

Releases exist for Linux (x86-64, ARM64) and macOS (Intel, Apple Silicon). Windows is not supported yet.

To install elsewhere or a specific release, pass options after `sh -s --`:

```sh
curl -fsSL https://get.istok.sh | sh -s -- --install-dir "$HOME/bin"
curl -fsSL https://get.istok.sh | sh -s -- --version v0.4.0
```

With Homebrew on macOS or Linux:

```sh
brew install vtimame/tap/istok
```

You can also download an archive from [GitHub Releases](https://github.com/vtimame/istok.sh/releases) and put the `istok` binary on your `PATH` yourself.

## 2. Connect your agent

Add Istok as an MCP server once, for your user. The same connection then works in every project. The actor ID tells Istok which agent did the work.

```sh
claude mcp add --transport stdio --scope user istok -- \
  istok mcp --actor-id claude --actor-name "Claude Code"
```

Check it with `/mcp` inside Claude Code.

</Tab>
<Tab>

```sh
codex mcp add istok -- \
  istok mcp --actor-id codex --actor-name "Codex"
```

</Tab>

Add this to `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "istok": {
      "command": "istok",
      "args": ["mcp", "--actor-id", "cursor", "--actor-name", "Cursor"]
    }
  }
}
```


The server lists the core workflow tools. Add `--tools full` to the `istok mcp` command if you want every tool, including knowledge writing and the code graph.

## 3. Add the hooks

For Claude Code and Codex, hooks keep the work across restarts and compactions. Install them once:

```sh
istok hooks install claude   # or: istok hooks install codex
```

When a session starts, the hook prints the interrupted work of the project, so the agent sees it before you say anything. For Claude Code the hooks also keep the Istok state in compaction summaries and link new commits to the task the agent is working on. With `--stop`, the agent is asked once for a handoff when it stops in the middle of a task.

The hooks are silent outside Istok projects. `istok hooks status` shows where they are installed; other settings and hooks in the agent's config are kept.

## 4. Tell the agent when to use it

MCP makes the tools available. Instructions tell the agent when to use them. Add this block to your global instructions: `~/.claude/CLAUDE.md` for Claude Code, `~/.codex/AGENTS.md` for Codex, User Rules in Cursor settings.

```md
## Working with Istok

Use Istok MCP tools for non-trivial work in repositories registered with Istok.

- Before starting, resolve the current project in Istok. If it is not registered, tell me and do not register it unless I ask.
- Reuse an existing task when one fits; otherwise create a focused task. Do not create tasks for questions or tiny edits.
- Start the task before implementing, and record meaningful progress, decisions and blockers.
- Before you stop, write a handoff: what is done, where you stopped, the next step.
- Validate the result through Istok and record the evidence. Complete the task only after validation passes.
- Do not copy Istok task state into TODO files or plan documents.
```

Istok's MCP server also sends the agent a short guide to its tools. Clients that support MCP server instructions, such as Claude Code, pass it to the agent. The block above is still worth adding: it says when you want Istok used, and it works in every client. A longer version is in [Working with your agent](/docs/en/guides/working-with-agents#when-the-agent-forgets-to-use-istok).

## 5. Register the project

Start the agent in your repository and ask:

<Prompt reply="Registered acme-api in Istok.">Register this project in Istok.</Prompt>

The agent registers the directory it was started in. Istok writes nothing into the repository. From a terminal, `istok init` does the same.

## 6. Give it a real task

Ask for something you would ask anyway:

<Prompt>GET /orders/{"{id}"} returns 500 when the order does not exist. Make it return 404 and keep 500 for other errors.</Prompt>

The agent creates a task, starts it, works, runs the tests through Istok, and completes the task with that evidence. For a quick question it just answers.

## 7. See what happened

```sh
istok task list
istok task show 1
```

`istok task list` shows the open tasks of the current project. `istok task show` prints one task with its history, every run, its checks and the linked commits.

## Update

```sh
istok update
```

Istok shows the current and new version with release notes and asks before installing. `--check` only checks; `--yes` installs without asking. Before replacing the binary Istok verifies the release signature, backs up the database and migrates it; if that fails, it puts the old binary and database back. If you use a custom database, pass it with `--database` or `ISTOK_DATABASE` so the right file is migrated.

Homebrew installs are updated with `brew upgrade istok`; `istok update` tells you so instead of replacing the binary. The plugin's own copy updates with `istok update` like any other install.

An open agent session keeps running the old `istok mcp` process, so start a new session after updating. A binary built from source cannot update itself; `istok update` explains how to install an official release.

## Uninstall

1. Remove the hooks: `istok hooks uninstall claude` (or `codex`).
2. Remove the MCP server from your agent, for example `claude mcp remove istok`.
3. Delete the binary: `rm ~/.local/bin/istok`, or `brew uninstall istok`.

With the plugin, run `/plugin uninstall istok@istok` in Claude Code instead of steps 1 and 2; it removes the plugin's copy of `istok` too.

Your data stays where it is: `~/.local/share/istok` on Linux (or `$XDG_DATA_HOME/istok`), `~/Library/Application Support/istok` on macOS. It holds the database, the code indexes, run artifacts and, if you sync, this device's sync key. Deleting it removes all projects, tasks, runs and knowledge on this machine and cannot be undone. Your repositories are not affected.
