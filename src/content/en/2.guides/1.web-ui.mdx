Most Istok activity happens inside MCP calls made by your coding agent. The web UI makes that work visible: which tasks exist, which agents are working on them right now, how each attempt was validated, and exactly what an agent was given when it started.

The UI is built into the `istok` binary. It reads the same local database as the CLI and MCP server, needs no account and no separate server, and is only reachable from your own machine.

## Open the UI

Run:

```sh
istok ui
```

Istok starts a local web server on `http://127.0.0.1:7700`, prints the address, and opens it in your default browser. The server keeps running in the foreground until you press `Ctrl+C`.

To print the address without opening a browser:

```sh
istok ui --no-open
```

To use another port:

```sh
istok ui --port 7800
```

`--port 0` picks a free port. The port can also be set with the `ISTOK_UI_PORT` environment variable.

If you keep Istok state in a custom database, point the UI at the same file:

```sh
istok ui --database /path/to/istok.db
```

Without `--database`, the UI uses `ISTOK_DATABASE` or the default database location, just like the other commands. See [Configuration](/docs/en/reference/configuration).

## Projects

The start page lists your Istok projects.

Each card shows the project name and its repository path, the number of open, blocked, and done tasks, how many runs are currently running or stale, and when the project last saw activity. You can sort projects by recent activity, name, or creation date.

## Tasks

Open a project to see its tasks. The list can be filtered by state (not done, open, blocked, done, or all) and by title or task number.

A task page shows the description, acceptance criteria, and notes rendered as Markdown, the full task history, the tasks it is blocked by and the tasks it blocks, and every run that worked on it.

From a project page you can also open **Knowledge**, a read-only catalog of the project's [knowledge](/docs/en/how-istok-works/knowledge) items with their status and kind.

## Runs

**Runs** in the top navigation is a feed of runs across all projects, grouped by day.

<BrowserFrame light={runsLight} dark={runsDark} alt="The runs feed of the Istok web UI with running, stale, succeeded and failed runs" url="127.0.0.1:7700/runs" class="not-prose my-8" sizes="(min-width: 1024px) 720px, 100vw" />

Filter it by state:

* **Running** — active runs whose agent is still sending heartbeats;
* **Stale** — active runs whose agent stopped sending heartbeats, so their lease has expired;
* **Succeeded**;
* **Failed & stopped** — failed, blocked, cancelled, and abandoned runs.

You can also narrow the feed by project name. For a stale run, the feed shows when its agent last sent a heartbeat instead of a duration.

## A run page

A run page shows who ran the attempt, when it started, how long it took, the Git branch and commit it started from, and the run's final summary. Below that are three tabs.

**Validations** lists the checks that were recorded for the run, whether each one passed, and the command behind it. This is where you see how a result was actually verified.

<BrowserFrame light={runLight} dark={runDark} alt="A run page in the Istok web UI showing passed validations" url="127.0.0.1:7700/runs" class="not-prose my-8" sizes="(min-width: 1024px) 720px, 100vw" />

**Executions** lists the commands the agent ran through Istok during the attempt.

**What the agent saw** shows the context snapshot captured when the task was claimed:

* the context budget and how much of it was used by durable context and code retrieval;
* the saved context records that were delivered, with their delivery mode and the reason each one was selected;
* the code snippets selected by retrieval, with syntax highlighting, file path, line range, and score;
* the knowledge briefing: titles and summaries of current project knowledge.

When an agent made a wrong assumption, this tab answers a practical question: was the right information missing, or was it there and ignored? See [Context](/docs/en/how-istok-works/context) for how the snapshot is assembled.

## Search and themes

Press `Ctrl+K` (`⌘K` on macOS) anywhere to open the search palette. Inside a project it searches tasks, knowledge, and projects; on other pages it searches projects.

The UI follows your system's light or dark preference. Use the theme button in the header, or press `D`, to switch.

## Live updates

You do not need to reload the page while agents work. When an agent creates a task, records progress, or finishes a run, the open page refreshes within about a second.

The indicator in the header shows whether live updates are connected. If the connection drops, the UI falls back to refreshing every few seconds until it reconnects.

## Abandon a stale run

A run stays active until its agent finishes it. If the agent session crashed or was closed, the run stops receiving heartbeats and becomes **stale**. A stale run still holds its task, and the task stays in progress until something closes the run.

The UI shows an **Abandon** action for stale runs in the runs feed, on the run page, and on the task page. Abandoning:

* closes the run with the `abandoned` status;
* releases the task so another agent can claim it;
* records the reason in the task history. The reason is optional; if you leave it empty, Istok records a default one.

The UI refuses to abandon a run whose agent is still sending heartbeats, so you cannot pull work out from under an agent that is still working. Abandoned runs remain part of the history.

The CLI equivalent is [`istok run abandon`](/docs/en/reference/run#abandon-a-run).

## Delete a project

Open a project, use the actions menu next to its name, and choose **Delete project**. Type the project name to confirm.

Deleting a project:

* removes it from the project list and releases its directory, so the directory can be initialized again;
* keeps its tasks, runs, and history in the database;
* does not touch any files in the repository.

The deletion is reversible:

```sh
istok project restore my-project
```

See [project](/docs/en/reference/project#restore-a-project) for details.

## Access and security

The UI listens only on the loopback address `127.0.0.1`. It is not reachable from other machines on your network.

There is no login and no access token. The UI is meant to be left running, often as a background service, and a token you have to look up every time would get in the way. Instead, the server protects you from websites in your browser:

* requests must address the UI by `127.0.0.1` or `localhost` and its port, which blocks DNS rebinding;
* API requests coming from another website's origin are rejected, which also prevents cross-site request forgery.

This does not stop other programs running on the same computer: any local process, under any user account, can read the UI's API. On a machine shared by several people, do not run the UI.

## Run the UI as a service on Linux

On Linux with systemd you can keep the UI running in the background as a user service, so it is always available at the same address:

```sh
istok ui service install
```

This writes a user unit named `istok-ui.service` to `~/.config/systemd/user/` (or `$XDG_CONFIG_HOME/systemd/user/`), enables it, and starts it. No `sudo` is required. Running `install` again updates the unit if anything changed and restarts the service on the current binary.

`install` accepts the same `--port` and `--database` options as `istok ui`:

```sh
istok ui service install --port 7800 --database /path/to/istok.db
```

A service does not inherit your shell's environment, so a database path chosen at install time (by flag or through `ISTOK_DATABASE`) is written into the unit as an absolute path.

Manage the service with:

```sh
istok ui service status
istok ui service restart
istok ui service stop
istok ui service start
```

Remove it completely with:

```sh
istok ui service uninstall
```

This stops and disables the service and deletes the unit file.

By default, systemd stops user services when you log out. To keep the UI running after logout, enable lingering for your user:

```sh
loginctl enable-linger
```

`istok ui service` is available on Linux only. On macOS, run `istok ui` directly.

### Updates and the service

After `istok update` installs a new release, it restarts the UI service automatically if the service is installed, active, and runs the binary that was just updated. A service that runs a different `istok` binary is left alone.

If the restart fails, the update itself still succeeds and Istok prints a warning. Restart the service manually:

```sh
istok ui service restart
```
